# 🧠 Mini NPU Simulator (MAC 연산 기반 패턴 판별기)

## 📌 1. 프로젝트 개요

* 컴퓨터는 그림의 '모양'을 보지 못하고 **숫자 배열**만 이해합니다. 이 프로그램은
  패턴과 필터(숫자 배열)를 **위치별로 곱하고 모두 더하는 MAC(Multiply-Accumulate)
  연산**으로 유사도 점수를 구해 십자가(Cross)와 X 패턴을 판별합니다.

* 3×3부터 25×25까지 다양한 크기를 처리하고, 크기별 연산 시간을 측정해 시간 복잡도
  **O(N²)** 를 직접 확인합니다.

* 외부 라이브러리 없이 표준 라이브러리(`json`, `time`, `math`, `re`, `os`, `sys`)만 사용합니다.

## 🛠️ 3. 구현 요약

### 3-1. 데이터 구조 — `Matrix` 클래스

* n×n 2차원 배열을 저장하고 `get(r, c)` / `set(r, c, value)`로 특정 위치의 값을
  읽고 씁니다. 3×3, 5×5, 13×13, 25×25 모두 같은 클래스로 처리합니다.

* `Matrix.from_rows()`가 배열 검증을 담당합니다. 리스트가 아님, **정사각형이 아님**,
  숫자가 아닌 값(`bool`·문자열), `NaN`/`inf`를 모두 `ValueError(사유)`로 알려줍니다.

### 3-2. 라벨 정규화 — `normalize_label()`

프로그램 내부의 표준 라벨은 **`Cross`, `X`** 두 가지입니다. `data.json`은 값이 이렇게
섞여 있습니다.

| 위치 | 원본 표기 | 정규화 결과 |
| :--- | :--- | :--- |
| `filters` 안의 키 | `cross` / `x` | `Cross` / `X` |
| `patterns`의 `expected` | `+` / `x` | `Cross` / `X` |

* 앞뒤 공백과 대소문자를 무시하고, 알 수 없는 값은 `ValueError`로 처리합니다.

* 출력과 PASS/FAIL 비교는 **항상 표준 라벨 기준**으로 합니다. (`+` 와 `Cross` 처럼
  표기가 달라 비교에 실패하는 일을 막기 위해서입니다.)

### 3-3. MAC 연산 — `mac()`

```python
def mac(pattern, filt):
    total = 0.0
    for i in range(pattern.size):
        for j in range(pattern.size):
            total += pattern.get(i, j) * filt.get(i, j)
    return total
```

* NumPy 없이 **이중 반복문**으로 구현했고, 곱셈·덧셈 횟수는 정확히 **N²** 입니다.

### 3-4. 점수 비교 정책 — `judge()` (epsilon)

* `abs(score_a - score_b) < 1e-9` 이면 **동점(UNDECIDED)** 으로 봅니다.

* `data.json` 분석에서 판정이 `UNDECIDED`이면 expected와 같을 수 없으므로 **FAIL**
  (동점 규칙)로 처리합니다.

### 3-5. 케이스 단위 검증 — 프로그램이 멈추지 않는 구조

`evaluate_pattern()`은 패턴 1건마다 아래를 검사하고, **문제가 있어도 예외를 밖으로
내보내지 않고 `FAIL(사유)`로 기록**한 뒤 다음 케이스로 넘어갑니다.

1. 키 형식(`size_N_idx`) → N 추출 / `input`, `expected` 키 존재
2. `size_N` 필터 존재 및 로드 성공 여부
3. `input`이 정사각 숫자 배열인지
4. **패턴 크기 = 필터 크기** 인지
5. `expected` 라벨 정규화 가능 여부

파일 없음·JSON 손상·최상위 구조 오류는 안내 메시지 후 **메뉴로 복귀**합니다.

### 3-6. 성능 측정 — `measure_mac()`

* `time.perf_counter()`로 **MAC 함수 호출 구간만** 10회 반복 측정해 평균(ms)을
  구합니다. 입력·출력·파일 읽기 시간은 포함하지 않습니다.

* 3×3은 기본 예시 배열, 5×5·13×13·25×25는 `data.json`의 필터와 패턴으로 측정합니다.

### 3-7. 모드 1 입력 검증

* 한 줄에 숫자 3개가 아니거나(개수 오류), 숫자가 아닌 값·`nan`/`inf`가 있으면
  `입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.` 를 출력하고
  **그 줄만 다시 입력**받습니다.

### 3-8. 신규 라벨 추가 및 확장 절차 (유지보수 가이드)

새로운 패턴 라벨(예: `Circle` 또는 `O`)을 시스템에 추가할 때는 아래 4단계 절차에 따라 수정 및 검증을 진행합니다.

1. **정규화 매핑 테이블(`LABEL_MAP`) 확장:**
   * `normalize_label()` 내부의 매핑 딕셔너리(`LABEL_MAP`)에 신규 표준 라벨과 허용할 별칭(소문자 기준)을 등록합니다.
   * 예: `"o": "Circle", "circle": "Circle", "0": "Circle"`
2. **`normalize_label()` 변환 및 예외 동작 확인:**
   * 앞뒤 공백 및 대소문자 혼합 입력(예: `" CIRCLE "`, `"O"`)이 표준 라벨(`"Circle"`)로 정상 반환되는지, 미등록 라벨 입력 시 `ValueError`가 발생하는지 단위 테스트로 검증합니다.
3. **판정(`judge()`) 및 출력 포맷 연동:**
   * 2개 이상의 다중 필터 비교가 필요한 경우 `judge()` 함수의 최댓값 및 차순위 점수 간 허용오차(`abs(best - second) < 1e-9`) 비교 로직으로 확장합니다.
   * `evaluate_pattern()` 및 결과 리포트 출력부에서 하드코딩된 라벨명(`Cross`, `X`) 대신 `LABEL_MAP.values()`의 표준 라벨 목록을 동적으로 순회하여 출력하도록 반영합니다.
4. **데이터 및 테스트 케이스 추가 검증:**
   * `data.json`의 `filters`(예: `"circle": [[...]]`)와 `patterns`(예: `"expected": "o"`)에 신규 케이스를 추가하고, 모드 2 실행 시 정상 로드 및 `PASS`/`FAIL` 판정이 의도대로 동작하는지 최종 확인합니다.

## 📝 6. 결과 리포트

### 6-1. 실패 원인 분석 (실패 3개: size_5_1, size_13_2, size_25_1)

* `data.json`의 6개 케이스 중 3개(`size_5_2`, `size_13_1`, `size_25_2`)는 PASS,
  3개(`size_5_1`, `size_13_2`, `size_25_1`)는 FAIL입니다. 실패 3건은 모두 같은
  유형으로, 판정이 `UNDECIDED`(동점)이어서 expected(`x`, `+`, `x`)와 일치하지
  못한 경우입니다.

* **원인을 세 갈래로 나눠 진단했습니다.**

| 분류 | 점검 내용 | 결론 |
| :--- | :--- | :--- |
| 데이터/스키마 문제 | 키 형식, 필터 존재, 정사각 여부, 크기 일치, 라벨 표기 | 모든 케이스 통과 → **원인 아님** |
| 로직 문제 | 라벨 정규화(`+`→Cross, `x`→X), 필터 선택, MAC 연산, PASS/FAIL 비교 | 정규화 후 비교가 정상 동작 → **원인 아님** |
| 수치 비교(부동소수점) | Cross 점수와 X 점수가 **동점**인지 | 3건 모두 해당 → **원인** |

* **동점이 진짜인지 확인했습니다.** 파이썬 `float`이 아니라 10진 정확 계산
  (`decimal.Decimal`)으로 다시 계산하면 세 케이스 모두 두 점수가 **수학적으로
  정확히 같습니다.** (size_5_1: 0.90 / 0.90, size_13_2: 7.50 / 7.50,
  size_25_1: 4.90 / 4.90) 즉 float 오차가 만든 가짜 차이가 아니라, 해당 패턴이
  Cross 필터와 X 필터 **양쪽과 똑같이 닮은** 데이터입니다.

* **epsilon이 없으면 어떻게 되는지도 확인했습니다.** `==`/`>` 로만 비교하면 float
  오차 때문에 점수가 미세하게 달라져 판정이 **우연히** 정해집니다.

| 케이스 | Cross 점수 | X 점수 | epsilon 없이 비교 | epsilon 적용 |
| :--- | :--- | :--- | :--- | :--- |
| size_5_1 | 0.9 | 0.8999999999999999 | Cross (expected X) | UNDECIDED |
| size_13_2 | 7.499999999999997 | 7.5 | X (expected Cross) | UNDECIDED |
| size_25_1 | 4.9 | 4.899999999999999 | Cross (expected X) | UNDECIDED |

* epsilon 없이도 3건이 FAIL이지만, 그 판정은 **오차 때문에 우연히 나온 값**이라
  신뢰할 수 없습니다. epsilon 정책을 쓰면 "두 필터로는 구분할 수 없다"는 사실이
  `UNDECIDED`로 정직하게 드러나고, 실패 원인이 "동점 규칙"이라고 명확히 남습니다.

* **왜 실패 0개가 되지 않았는가:** 정규화와 epsilon 정책은 *표기 불일치*와
  *부동소수점 오차*를 해결해 줄 뿐, 두 점수가 **원래 같은 데이터** 자체를 구분하게
  해 주지는 못합니다. 과제 규칙(동점 = `UNDECIDED` = FAIL)에 따라 이 3건은 FAIL이
  맞는 결과입니다.

* **개선 방향(데이터/필터 측):** 필터 값을 조정(예: 중심 가중치 구분)하거나 동점일 때
  보조 기준(비교 규칙)을 정하면 구분할 수 있습니다. 다만 이는 `data.json`과 판정
  규칙 자체를 바꾸는 일이라, 이번 구현에서는 규칙을 그대로 따르고 원인만 분석했습니다.

* **정규화의 효과:** `expected`가 `+`/`x`, 필터 키가 `cross`/`x`처럼 표기가 달라
  정규화 없이 문자열을 비교하면 PASS여야 할 `size_5_2`, `size_25_2`
  (expected `+`, 판정 `Cross`)가 **FAIL로 잘못 판정**됩니다. 정규화로 이 문제를
  제거했습니다.

### 6-2. 성능 분석 (평균/10회) 및 시간 복잡도

| 크기(N×N) | 평균 시간(ms) | 연산 횟수(N²) | 시간 ÷ 연산 횟수(ms/회) |
| :--- | :--- | :--- | :--- |
| 3×3 | 0.0010 | 9 | 0.000111 |
| 5×5 | 0.0022 | 25 | 0.000088 |
| 13×13 | 0.0127 | 169 | 0.000075 |
| 25×25 | 0.0454 | 625 | 0.000073 |

* **O(N²) 근거:** MAC은 N×N 이중 반복이라 곱셈·누적 횟수가 정확히 N²입니다. 크기가
  커질수록 시간도 연산 횟수에 맞춰 증가합니다. 13×13 → 25×25는 연산 횟수가 약
  **3.70배**(169→625)이고, 측정 시간은 약 **3.57배**(0.0127→0.0454ms)로 거의
  비례합니다.

* **큰 크기에서 일정해지는 값:** 시간 ÷ 연산 횟수가 13×13(0.000075)과
  25×25(0.000073)에서 거의 같습니다. 1회 곱셈·누적에 드는 시간이 일정하다는
  뜻이고, 이것이 총 시간이 N²에 비례한다는 증거입니다.

* **작은 크기(3×3, 5×5)에서 오차가 큰 이유:** 연산량이 너무 작아 함수 호출과 타이머
  호출 같은 **고정 비용**이 비중을 크게 차지하고, 측정값도 실행마다 흔들립니다.
  (같은 3×3을 모드 1 실행에서 0.0018ms로 측정한 적도 있습니다.) 그래서 정확한
  비례 확인에는 연산량이 큰 구간(13×13 이상)이 더 적합합니다.

* **의미:** 한 변의 길이가 2배가 되면 연산량은 약 4배가 됩니다. 실제 AI 모델처럼
  수백×수백 필터를 수천 개 쓰면 연산량이 폭발하고, 이 단순 반복 곱셈·덧셈을
  동시에(병렬) 처리하도록 만든 전용 칩이 **NPU**입니다.

## 🎓 7. 학습 목표 설명

* **MAC 연산이란, AI에서 왜 중요한가:** 곱하고(Multiply) 결과를 누적해서
  더하는(Accumulate) 연산입니다. 필터 연산의 핵심이라 이미지 한 장에도 수억 번
  필요하고, 이 연산을 빠르게 처리하는 것이 AI 칩 성능을 좌우합니다.

* **유사도 점수 계산 원리:** 같은 위치의 값끼리 곱해 더하면, 두 배열이 **같은
  위치에서 함께 큰 값**을 가질수록 점수가 커집니다. 십자가 입력에 십자가 필터는
  5점, X 필터는 1점이 나오는 식입니다.

* **라벨 규칙 해석과 정규화 이유:** `data.json`은 필터 키(`cross`, `x`)와
  expected(`+`, `x`)의 표기가 다릅니다. 내부에서 `Cross`/`X`로 통일해야 표기 차이
  때문에 맞는 판정이 FAIL로 처리되는 일을 막을 수 있습니다.

* **부동소수점 오차와 epsilon:** 0.1 같은 값은 이진수로 정확히 표현되지 않아
  `0.3+0.3+0.3`이 `0.8999999999999999`가 되는 식의 오차가 생깁니다. `==` 비교는
  신뢰할 수 없으므로 `abs(a-b) < 1e-9`처럼 허용오차로 비교합니다.

* **O(N²) 설명:** 6-2의 표처럼 연산 횟수가 N²이고 측정 시간이 그에 비례합니다.

* **실패 원인 분리 진단:** 실패가 나면 ① 데이터/스키마(키·크기·라벨) → ② 로직
  (정규화·필터 선택·연산) → ③ 수치 비교(오차·동점) 순서로 좁혀 갑니다. 이번에는
  ①, ②가 정상이고 ③(동점)이 원인임을 6-1에서 확인했습니다.
